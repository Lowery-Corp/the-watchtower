# Watchtower Event Contract v1

## Endpoint

```http
POST /api/v1/webhooks/events
Content-Type: application/json
X-Watchtower-Service: scrappy
X-Watchtower-API-Key: <one-time managed key value>
X-Request-ID: optional-safe-correlation-id
```

`X-Watchtower-Service` is always required. Preferred senders use exactly one managed API-key header and omit legacy timestamp/signature headers. Raw key material is disclosed only when the owner creates the key and must be sent only over TLS.

A managed key authenticates one profile and may optionally be bound to one service. The source slug must resolve to an active service owned by that profile, and any service binding must match. Unknown, malformed, expired, revoked, cross-profile, inactive, or incorrectly bound credentials all fail with the same generic `401` response.

## Temporary legacy HMAC mode

Legacy senders omit `X-Watchtower-API-Key` and send:

```http
X-Watchtower-Timestamp: 1784404800
X-Watchtower-Signature: v1=<64 lowercase hexadecimal characters>
```

The source slug must be present in both deployment-only maps:

1. `WATCHTOWER_WEBHOOK_SECRETS`, containing its HMAC secret; and
2. `WATCHTOWER_LEGACY_WEBHOOK_PROFILES`, containing the owning profile UUID.

The slug must also resolve to an active service in that profile. Legacy HMAC exists only as an explicit compatibility path; new integrations should use managed keys. There is no unattributed fallback.

## Envelope

```json
{
  "spec_version": "1.0",
  "event_id": "0c34b762-04f9-4df5-80a0-7ff773d7e13d",
  "event_type": "service.heartbeat",
  "source": "scrappy",
  "subject": "api-1",
  "occurred_at": "2026-07-18T20:00:00Z",
  "severity": "info",
  "environment": "production",
  "correlation_id": "trace-123",
  "data": {
    "status": "healthy",
    "latency_ms": 12
  }
}
```

Rules:

- `spec_version` must be `1.0`.
- `event_id` must be a UUID generated by the source and remains the idempotency key for that source.
- `event_type` and `source` use lowercase dot, underscore, or hyphen-separated identifiers.
- The authenticated `X-Watchtower-Service` must equal the envelope `source`.
- `occurred_at` must be a timezone-bearing RFC3339 string and is normalized to UTC; Unix timestamps and numeric strings are rejected.
- `severity` is one of `debug`, `info`, `warning`, `error`, or `critical`.
- `data` must be a JSON object and remains unflattened in PostgreSQL JSONB.
- Non-finite numeric tokens (`NaN`, `Infinity`, and `-Infinity`) are rejected throughout `data` and extension fields.
- Unknown top-level extension fields are preserved in the immutable raw payload.
- The default maximum raw body is 262,144 bytes before parsing.

## Legacy HMAC signature algorithm

Sign the exact transmitted body bytes. Do not parse and reserialize the body after signing.

1. Compute lowercase hexadecimal `SHA-256(body)`.
2. Construct this UTF-8 canonical value, including newlines:

```text
v1
<TIMESTAMP>
<SERVICE_SLUG>
<BODY_SHA256_HEX>
```

There is no trailing newline after the body digest.

3. Compute lowercase hexadecimal `HMAC-SHA256(service_secret, canonical_value)`.
4. Send the signature as `v1=<hex digest>`.

Watchtower uses constant-time comparison and rejects signatures outside the configured freshness window, which defaults to 300 seconds.

## Legacy standard-library sender example

```python
import hashlib
import hmac
import json
import os
import time
import urllib.request
import uuid
from datetime import UTC, datetime

service = "scrappy"
secret = os.environ["WATCHTOWER_SIGNING_SECRET"]
timestamp = str(int(time.time()))
payload = {
    "spec_version": "1.0",
    "event_id": str(uuid.uuid4()),
    "event_type": "service.heartbeat",
    "source": service,
    "subject": "api-1",
    "occurred_at": datetime.now(UTC).isoformat().replace("+00:00", "Z"),
    "severity": "info",
    "environment": "production",
    "correlation_id": None,
    "data": {"status": "healthy"},
}
body = json.dumps(payload, separators=(",", ":")).encode()
body_digest = hashlib.sha256(body).hexdigest()
canonical = f"v1\n{timestamp}\n{service}\n{body_digest}".encode()
signature = "v1=" + hmac.new(
    secret.encode(), canonical, hashlib.sha256
).hexdigest()

request = urllib.request.Request(
    "http://127.0.0.1:8010/api/v1/webhooks/events",
    data=body,
    method="POST",
    headers={
        "Content-Type": "application/json",
        "X-Watchtower-Service": service,
        "X-Watchtower-Timestamp": timestamp,
        "X-Watchtower-Signature": signature,
    },
)
with urllib.request.urlopen(request, timeout=10) as response:
    print(response.read().decode())
```

## Acknowledgement

First accepted submission:

```json
{
  "event_id": "8f161b67-477c-4746-a78f-1fa6ec15f00d",
  "source_event_id": "0c34b762-04f9-4df5-80a0-7ff773d7e13d",
  "status": "accepted",
  "request_id": "f4c42fe4-6bc2-4c14-a76b-23f7ac48134d"
}
```

A retry with the same authenticated source and source `event_id` returns HTTP `202` with the same canonical `event_id` and `status: duplicate`. It does not create another event or outbox row.

## Rejections

- `401`: missing, unknown, malformed, expired, revoked, stale, mismatched-source, cross-profile, incorrectly bound, or invalid authentication. Managed-key source state is not enumerated.
- `403`: a valid legacy HMAC sender's mapped source exists but is inactive.
- `409`: the authenticated source reused an existing source event ID with different content.
- `413`: raw request body exceeds the configured limit.
- `422`: authenticated body is not a valid version-one event envelope.
- `429`: the application or edge request budget is exhausted; callers should honor `Retry-After` when present.

The default application budget is 60 authenticated requests per managed key or mapped legacy sender per 60-second process-local window. The Compose Nginx edge independently enforces 60 requests per minute per client IP with a burst of 20 and rejects bodies above 256 KiB before proxying. Multi-replica production deployments require an equivalent shared ingress or distributed application limit because the in-process limiter is not global.

Authentication failures deliberately use one generic message. Request bodies and authentication headers must not be logged.
